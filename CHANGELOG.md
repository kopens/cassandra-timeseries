# Changelog

Notable changes to **cassandra-timeseries**, the industrial time-series fork of Apache Cassandra.

This file covers the *fork's* changes only. Upstream Apache Cassandra's own entries live in
[`CHANGES.txt`](CHANGES.txt), which follows the ASF convention and gains a batch of entries every
time `main` is merged with `apache/cassandra`'s `cassandra-6.0` branch. The two are deliberately not
synchronised: `CHANGES.txt` answers "what changed in Cassandra", this file answers "what changed in
our build".

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Entries under a release
heading are generated by CI from commits carrying a `Changelog:` git trailer — see
[CONTRIBUTING.md](CONTRIBUTING.md#changelog-entries).

## Unreleased

### Changed

- Merged upstream `apache/cassandra` `cassandra-6.0` (28 commits), which raises two bundled
  dependencies: Caffeine 3.1.8 → 3.2.4 and lz4-java 1.10.1 → 1.11.2. **Deploying only
  `apache-cassandra-6.0.0.jar` into an existing install is no longer enough** — `NoSpamLogger` calls
  `Expiry.writing`, added in Caffeine 3.2, so a node left with `caffeine-3.1.8.jar` on its classpath
  fails at startup with `NoSuchMethodError`. Replace the dependency jars too, and delete the old
  ones; see [doc/timeseries/production-rollout.md](doc/timeseries/production-rollout.md) §0.5.

### Fixed

- `DROP TABLE <base>__chunks` is refused while the table's tiering policy is still attached. The
  chunk table holds the only copy of every tiered row — the base copies are deleted as they are
  encoded — and the sweeper would recreate it empty on its next cycle, truncating history with no
  error anywhere. Detach the policy (`ALTER TABLE ... WITH extensions = {}`) to unlock the drop.

## [v6.0.0] - 2026-08-29

First release of the fork, against Apache Cassandra 6.0.0.

Each entry below is a summary; `CHANGES.txt` carries the full text, and the design documents in
[doc/timeseries/](doc/timeseries/) carry the reasoning.

### Added

- **Native time-series CQL functions**: `time_bucket`, `first`, `last`, `delta`, `rate`,
  `derivative`, `percentile`, `time_weighted_average`, `variance`, `stddev`, `histogram`,
  `approx_count_distinct`, `counter_delta`, `counter_rate`, `corr`, `covar_pop`, `covar_samp`,
  `regr_slope`, `regr_intercept`, `regr_r2` and `integral`.
- **Gap-filling**: `GROUP BY time_bucket_gapfill(width, ts, start, finish)` materialises empty
  buckets, with `locf()` and `interpolate()` fill policies.
- **SAI full-text search**: an `index_analyzer` index option (ngram/standard/cjk/keyword presets, or
  a JSON config) enabling substring `LIKE` — `'%fragment%'`, `'prefix%'`, `'%suffix'` — on text
  columns, Korean included, served by n-gram recall with a raw-value precision recheck.
- **TimeSeriesCompactionStrategy (T1)**: time-window classification with in-window UCS delegation
  and whole-window retention drops.
- **TSCS window freeze (T2)**: closed windows compact to a single sstable per window, with a
  `WindowFrozenListener` post-commit hook, a far-future timestamp guard (`max_future_window`,
  default 1d), and reclamation of data already expired at the moment a closed window freezes.
- **TSCS late-data isolation (T3)**: flush and streaming split sstables at time-window boundaries by
  write timestamp, so every sstable belongs to exactly one window; legacy spanning sstables are
  split-rewritten per window in the background.
- **Tiered storage chunk store (SP2)**: a per-table `timeseries_tiering` policy, a background
  re-encoder compacting closed windows into chunk shadow tables (`<table>__chunks`) with late-row
  merge, cold-window expiry and a consistency quorum floor, plus `nodetool retier` /
  `nodetool tieringstatus` and the `system_views.timeseries_tiering` virtual table.
- **Transparent tiered reads (SP3)**: `SELECT` on a tiering-enabled table merges decoded chunk rows
  with hot rows before aggregation — ranges, point lookups, aggregates, gap-fill, and `LIMIT`/`DESC`
  across hot and cold, including across pages.
- **chimp128 chunk codec** (v2) with version-dispatched decoding, and a codec bake-off report.

### Changed

- **BREAKING** — the chunk codecs are unified on chimp128. Chunks written by an earlier build are
  unreadable, and a `SELECT` that hits one now fails loudly instead of skipping it as corrupt: drop
  the `<table>__chunks` table (that data is not recoverable) and let tiering re-run. The
  `timeseries_tiering` `codec` option is gone, and a policy JSON still setting it is rejected by
  name.
- **BREAKING** — tiered storage re-encodes every regular column into one columnar chunk per window
  rather than a single double column, so any supported table shape is compressible, with an
  opaque-bytes fallback for blob/uuid/timeuuid/frozen collections. Single-column (v1/v2) chunks are
  neither written nor read any more. On a tiered table, writes that would tombstone data past the
  hot window are now rejected — cold data is immutable once chunked, and `cold_window` is the only
  retention mechanism for it.

### Fixed

- Chunk table creation wrote a cluster metadata log entry that could not be parsed back, stopping
  schema propagation cluster-wide and preventing the writing node from replaying its own log at
  startup. Chunk tables are now created with real `CREATE TABLE IF NOT EXISTS` DDL, which
  round-trips. **The fix does not repair an entry already written** — the metadata log is
  append-only, so a node that created a chunk table on an earlier build must be rebuilt from an
  empty data directory.
- The incremental tag scan's failure lever is the token span rather than the page `LIMIT`, so an
  expensive stretch is stepped over after finitely many halvings instead of stalling new-tag
  discovery permanently.
